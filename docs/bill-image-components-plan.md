# 首页票面改用自绘组件图（实施计划）

**状态：已实现（2026-10-29）。与方案的实测偏差见文末「实施偏差」一节。**

目标：把首页票面里由代码「画」或「排」出来的元素，换成站长自绘的组件图，
让票面更接近真实美元纸币。**位置、尺寸、点击区、无障碍标签全部沿用现有几何**，
只替换视觉层。

配套文档：

- 设计规范与红线变更 → `docs/design-banknote-plan.md` §0.6
- 上线后换图流程 → `docs/maintenance-guide.md` §9
- 为什么这些图不走 R2 流程 → `docs/media-optimization.md`

## 2. 现状

`BillSheet.astro` 目前有 4 种渲染器，按 `zone.kind` 选择：

| kind | 渲染内容 |
| --- | --- |
| `portrait` | `<img>` 头像（`/brand-avatar.webp`） |
| `seal` | 原创同心环 + 首字母 |
| `marker` | 参数化 SVG 墨水瓶（`inkwellMark()`） |
| 其余 | `.bill__text` 文本，字号/字距/压缩由毫米解算器给出 |

方框 `Z5–Z8`（四角 `100`）是文本渲染；票面背景由 `guillocheTile()` /
`cornerFlourish()` / `scrollBand()` 三个参数化纹样拼成。

**新增一个 `art` 通道即可覆盖全部替换需求**，不需要为每种图新增 `kind`。

## 3. 数据模型

在 `src/lib/bill-config.ts` 的 `BillZone` 上加一个可选字段：

```ts
export interface BillZoneArt {
 /** 站内绝对路径，必须以 / 开头（归一化时按此白名单校验） */
 src: string;
 /** 填充方式，默认 contain；签名这类带大量透明留白的用 cover */
 fit?: "contain" | "cover" | "fill";
 /** 与纸面的混合方式，默认 multiply（凹版印刷是墨压纸） */
 blend?: "normal" | "multiply";
 /** 0–1，默认 1 */
 opacity?: number;
 /** object-position，默认 "center"；如 "center 30%" 用于保护头部不被裁 */
 align?: string;
}

export interface BillZone {
 // …原有字段不变…
 /** 组件图；给了就用图片渲染，忽略文本解算 */
 art?: BillZoneArt;
}
```

**关键设计：`art` 是可选的，删掉即回退到原来的文字/图形渲染。**
这是整套方案的回滚开关，不需要改代码就能退回。

## 4. 渲染

`BillSheet.astro` 的 `inner` 分支加在最前面：

```
art.src 存在 → <span class="bill__art"><img src alt="" …></span>
否则        → 现有 portrait / seal / marker / text 分支
```

要点：

- `<img alt="">` + 外层已有 `aria-label`，不重复播报
- `object-fit` 取 `art.fit`，`object-position` 取 `art.align`，
  `mix-blend-mode` 取 `art.blend`，`opacity` 取 `art.opacity`
- 图片区块**不参与**文本解算：`BILL_TEXT_MM`、`BILL_ZONE_ADVANCE`、
  `BILL_ZONE_TRACKING` 对它无效（保留不动，回退时即用）
- `width`/`height` 属性按 §5 的输出像素写死，避免 CLS
- `loading="eager"` + `decoding="async"`（首屏元素，不偷懒加载）

## 5. 资源处理

### 5.1 位置

从 `.reference/zujian2/` 移到 **`public/bill/`**。

理由：这是**布局资源**，跟随代码一起部署，走 assets 层；
不放进 R2/D1 —— 那套是给用户上传的封面/背景图用的（见 `media-optimization.md`）。

`.reference/` 在 `.gitignore` 里，留在那儿不会发布。

### 5.2 处理流程

1. 保留 alpha 通道
2. **按 alpha 边界裁掉透明留白**（8 张图都有大片透明边，不裁会导致 `contain` 后画面偏小）
3. 缩到 2× 显示尺寸
4. 导出 WebP q85

### 5.3 目标尺寸

按票面渲染宽 1184px（= 156mm，7.59 px/mm）换算：

| 用途 | 目标盒 (mm) | 1× px | 2× 输出 |
| --- | --- | --- | --- |
| 整票边框 | 156 × 66.3 | 1184 × 503 | 2400 × 1020 |
| `Z1` 肖像 | 46.0 × 58.0 | 349 × 440 | 720 × 900 |
| `Z2` 大 `100` | 26.0 × 19.0 | 197 × 144 | 420 × 300 |
| `Z9` 徽记 | 21.0 × 18.6 | 159 × 141 | 340 × 300 |
| `Z11` 签名 1 | 22.6 × 6.4 | 172 × 49 | 360 × 110 |
| `Z12` 签名 2 | 24.0 × 6.4 | 182 × 49 | 380 × 110 |
| `Z14` 墨水瓶 | 14.1 × 14.4 | 107 × 109 | 230 × 230 |
| `Z22` 羽毛笔 | 待测（约 12 × 14） | ≈ 91 × 106 | 待定 |

体积目标：单张 ≤ 80 KB，整票全部组件图 ≤ 400 KB。

### 5.4 缓存头

`public/_headers` 增加一条（文件名不带内容哈希，因此不用 `immutable`）：

```
/bill/*
  Cache-Control: public, max-age=604800, stale-while-revalidate=2592000
```

> `tests/unit/static-headers.test.ts` 只校验 `public/*.js`，图片不受该闸门约束，
> 但仍需手动加到 `_headers`，否则每次导航都会回源校验。

### 为什么签名用 `cover` 而不是 `contain`

`doubao_image_1.png` 是「手写签名 + 印刷职衔」两行，但画布是正方形，
签名只占上方约 1/3，下面全是透明区。按 alpha 裁边后仍有留白。

用 `contain` 放进 22.6×6.4 的盒子里，图会被缩到 6.4mm 高、宽只剩 6.4mm，
字小到看不清；用 `cover` + `align: "center top"` 则铺满盒子、
裁掉的正是下方空白 —— 这才是正确的用法。

## 7. 需要新增 / 关闭的区块

### 7.1 关闭四个角

`Z5` / `Z6` / `Z7` / `Z8` 置 `enabled: false`。

**副作用**：这四处原本分别是「返回首页」「读书笔记」「订阅 RSS」「看看说说」。
关掉后首页票面少四个入口 —— 但站点头部导航与右下角浮动菜单仍在，
`/rss.xml` 与 `/shuoshuo` 依旧可达。

### 7.2 新增羽毛笔区块 `Z22`

现有 18 个区块里没有羽毛笔的位置。做法：

1. 在 `scripts/measure-bill-reference.py` 的 `FEATURES` 里加一条
   `Feature("羽毛笔", "Z22", (<窗口 mm>))`
2. 跑 `py scripts/measure-bill-reference.py` 拿到墨迹矩形
3. 按「墨迹 + 横向 1.0mm / 纵向 0.7mm 内边距」换算成区块
4. 定为纯装饰（`href: ""`、`enabled: true`、无 `art` 之外的交互），
   渲染成 `<span>` 而非 `<a>`

> 坐标不能拍脑袋定 —— 本项目已经吃过一次「以为那里没东西」的亏
> （`Z14` 墨水瓶），必须先量。

| 风险 | 处理 |
| --- | --- |
| 图片比例与盒子不符导致变形 | 只用 `contain` / `cover`，不用 `fill`（仅整票边框例外）；验收逐块目视 |

## 14. 实施偏差（2026-10-29 实现完成后补记）

实现与上文方案一致的部分不再重复；以下是与方案**不同**的地方及理由：

1. **签名图源图是「上下两组」而非「左右各一」**（§6 替换表、§待定项 1 的前提有误）。
   `doubao_image_1.png`（2173×1088）实际是一整张画布上按阅读顺序排了
   「Geithner 签名 → Secretary of the Treasury. → Rios 签名 → Treasurer of the
   United States.」四行，左右切半会拦腰截断文字。实际改为在 y=595（组间空白）上下切分。
   两个独立点击区（Z11→归档、Z12→最新一篇）按决策保留，未合并。
2. **签名 `fit` 用 `contain` 而非 `cover`**。`cover + align: "center top"` 的方案建立在
   「正方形画布、签名只占上方 1/3」的误判上；实际按 alpha 裁边后内容比例 ≈3.9/4.6，
   与盒子（3.53/3.75）几乎一致，`cover` 会裁掉职衔下缘。`contain` 完整显示，
   纵向余量仅约 0.3–1mm。
3. **羽毛笔墨迹的测量方法换了**。`measure-bill-reference.py` 的灰度法在该窗口饱和
   （羽毛笔与 “States of America” 铭文、独立宣言文字同窗，无法分离，见
   `.reference/bill/measured.json` 的 `窗口饱和` 标记）。实际改用彩色归一化参考图
   （由 `2.webp` 以同一套转正/裁剪管线重新生成）按「低饱和浅色羽毛 vs 金色安全线」
   分割测得墨迹 98.0–109.0 / 24.5–33.8 mm，加横向 1.0 / 纵向 0.7 mm 内边距后
   区块为 97.0, 23.8, 13.0, 10.7 mm。测量脚本 FEATURES 里的 `羽毛笔` 条目已保留，
   供后续复核。
4. **整票边框与肖像没达到 2× 目标尺寸**。雕版密布线条的图在 WebP q85 下远超 80 KB，
   降 q 到底也不够。流水线改为「降质阶梯（85→25）→ 降尺寸阶梯（1→0.6×）」自动权衡，
   并对 alpha < 24 的透明噪点连同 RGB 清零（体积大头之一）。实际产出：
   `frame.webp` 1440×612 q40（目标 2400×1020）、`portrait.webp` 504×438 q32
   （目标 720×900），其余 6 张达成 2× 目标 q85。合计 319.7 KB ≤ 400 KB 红线。
5. **`<img>` 未写死 `width`/`height` 属性**（§4）。区块是绝对定位的百分比盒，
   img 以 CSS `100%×100%` 填充，几何不依赖图片加载，本就无 CLS；
   而 art 可由后台改路径，写死尺寸反而会错。
6. **归一化的继承语义**：`art` 键缺省 = 沿用默认组件图（部署后旧的 DB 配置自动获得新图）；
   显式给出但无有效 src = 删除（后台清空即回退文本渲染）。`frameArt` 同理，
   显式空串 = 停用边框图并自动恢复参数化纹样。
7. **纯装饰区块渲染成 `pointer-events: none` 的 span**。Z22 与 Z18 在真钞上本就叠压，
   装饰层不挡下层链接的点击。
8. 顺手修复：`tests/unit/view-transitions.test.ts` 做了一次 biome 格式化
   （先前未提交改动引入的 format error，不修 `biome check` 闸门不绿）。

## 15. 第二次微调：按原版网格比对重排（2026-10-29 同日）

站长反馈「整体样式与原版不符、羽毛笔过小、肖像不要椭圆、报头文字要独立成块、
`doubao_image_4.png` 要上右下角」，因此做了一轮**以测量为准**的重排。

### 15.1 方法：网格划分对比（可复现）

新增 `scripts/grid-compare.py`：把 `DEFAULT_BILL_ZONES`（百分比 → 毫米）与参考图
（`.reference/bill/reference-color.png`，10 px/mm）放在同一张 **12 列 × 5 行**
（13.00 × 13.26 mm/格）网格上：

- 参考图侧按 Otsu 暗像素密度分档（稀疏 ≤0.10 < 中等 < 0.46 ≤ 密集），
  阈值取在分布断层里（不用分位点，p25 正好切在细铭文中间会把结论判反）
- 页面侧按区块覆盖率分档（<0.10 没盖到 / <0.35 偏小偏位 / >0.50 整格占满）
- 逐格标 `MISSING / OVER / PARTIAL / OK`，输出 `grid-diff.json` +
  `grid-diff.png`（红=漏、蓝=白占、黄=偏小），并做区块级墨量归因

**调整前**：MISSING 7 / OVER 0 / PARTIAL 8 / OK 45
**调整后**：MISSING 5 / OVER 1 / PARTIAL 6 / OK 48（脚本每次现读配置，可随时复跑）

剩余 MISSING 全部是「四角 100 由 `frame.webp` 画死、不设区块」与「SERIES 2009
是硬编码装饰文字」两处，属既定设计；唯一 OVER 是羽毛笔区块盖住参考图里的浅色羽毛

### 15.2 测量：第二版结构尺寸

### 15.3 行为与样式改动

1. **肖像去掉椭圆遮罩**：`portraitShape` 默认改 `"plain"`（归一化同步），
   原图按 `cover` 直接铺进区块，矩形硬边保留。
2. **报头文字独立成区块 Z23**：删除 `BillSheet.astro` 的 `.bill__masthead`
   硬编码与对应 CSS，改由 `INSCRIPTIONS.Z23` + `BILL_TEXT_MM.Z23 = 3.0` +
   `BILL_ZONE_TRACKING.Z23 = 0.09` 走文本解算（实测 `--insc:2.747cqw` → 字高 3.0 mm，

3. **区块渲染顺序改为「印刷顺序」**：羽毛笔是底纹级元素，必须排在 Z1/Z2 之前，

4. **Z8 复用为铜色大 100**：`href: ""`、`ariaLabel: ""` → 渲染成

5. **资源**：新增 `big-100.webp`（340×93，15.5 KB）；`quill.webp` 目标尺寸提到

   单张均 ≤80 KB。期间发现 `frame.webp` 被外部改成 2400×1020 / 1.0 MB，

## 16. 第三轮：肖像直出 + 层序 + 交互（2026-10-29 第三版）

站长六项要求逐条落地，**几何全部来自测量，不目测**。

### 16.1 肖像：从「流水线产物」改回「原图直出」

| 旧 pipeline（`prepare-bill-art.mjs`） | 现在 |
| --- | --- |
| `trim(threshold:10)` 裁掉 alpha 留白（−1.3% 面积） | **不裁**，保留 1374×1191 全画布 |
| alpha<24 的透明噪点连同 RGB 清零 | 只清 alpha<8（肉眼不可见，省 66 KB） |
| `resize inside 720×900` → 实际被宽度卡成 720×626 | 等比缩到 **760 宽 × 659 高**（44 mm 区块的 1.4×，2× 需 1120 宽但单图 ≈400 KB） |
| 体积超限后降到 0.7× / q32（504×438 / 80 KB） | 760 宽 / q64 / aq30 → **198 KB** |
| `cover + center 30%`，椭圆遮罩（上一版已去遮罩） | `cover + center bottom`，**人像下缘贴票面底边** |

- 原图 alpha 内容**底边留白 0 px**（胸腔直接出血到画布末行），所以「图片底边对齐票面底边」= 人像下缘正好压线，无需额外位移。
- 单图 198 KB 突破了原定 80 KB 单张红线（`public/bill` 合计 ≈ 507 KB）。原因：这张是整票最重的雕版排线图，760 宽下即使 q8 也要 128 KB，压到 80 KB 只能退到 480 宽（等效 1.4× 且 q48）。**要 2× 清晰度需 1120 宽 ≈ 400 KB，需要站长授权。**

### 16.2 可交互区块：Z22 / Z23

| 区块 | 之前 | 现在 |

| Z22 羽毛笔 | `href: ""` → 装饰 span、`pointer-events:none` | `href: "/shuoshuo"`、`aria-label "看看说说"` → 渲染成 `<a>`，有 hover 中文提示 |
| Z23 报头铭文 | `href: ""` → 装饰 span | `href: "/blog"`、`aria-label "浏览文章归档"` → `<a>` |

### 16.4 羽毛笔：高度达标

- 逐列色度剖面 + 40.8° 斜边拟合复核：整根羽毛 **87.3–120.3 / 13.4–42.4 mm，高 29.0 mm**
  （旧值 15.6–44.4 的上界被金色安全线带拖高、下界落进墨水瓶唇线，两个误差刚好抵消）
